# 01 输入来源锁定与内容清单

## 文件优先级
1. 本轮上传且明确指向的图片、PPT、提示词；
2. 当前用户特别指定的某份已确认母版（如有）；
3. 本轮明确要求用于参考的材料；
4. 更早的项目文件或模型知识：默认**不可作为内容来源**。

建立 `manifest.json`，至少包含：
- `source_image`: 当前图像的绝对/相对路径；
- `source_pptx`: 若是局部修改，用户指定的母版路径；
- `mode`: `rebuild` 或 `modify`；
- `expected_title`: 原图顶部主标题原文；
- `expected_slide_count`: 原图通常一张对应一页，除非用户指定不同；
- `required_text`: 图内必须保留的关键术语、模块名称、技术输出；
- `modules`: 标注各模块的名称、分组、入边/出边；
- `allowed_changes`: 局部修改时唯一允许变化的区域。

### 预先核对
- 实际打开/查看源图，能准确说出**图片的原始标题**、三到五个关键模块名称。
- 不能把领域相近的老资料当本轮来源；即使存在旧资料也不引用，除非用户要求。
- 模块数量、分区数量、主要流程顺序必须来自原图，不能从旧版 PPT 推断。
- 引用原提示词时，不要覆盖当前图像独有的专业内容。

### 可复用清单样例
`../examples/manifest.example.json` 仅示范字段结构；实际项目须从当前源图填写，**禁止直接沿用样例文字**。
